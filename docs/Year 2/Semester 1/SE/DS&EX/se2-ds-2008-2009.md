## Question de cours (4,5 points)

**1)** Quels sont les deux modes d'exécution d'un processus sur un ordinateur ? (1 point)

**2)** Quand est-ce qu'une commutation de contexte est lancée ? (1,5 points)

**3)** Que signifient les acronymes suivants : API, SVC, PCB, IPC ? (1 point)

**4)** Pour lancer en parallèle plusieurs traitements d'une même application, vous avez le choix entre les appels système `fork()` et `pthread_create()`. Laquelle des deux possibilités choisir ? Pourquoi ? (1 point)

<details>
<summary>Correction</summary>

**1)** Deux modes d'exécution :

1. **Mode utilisateur** : restrictions d'accès aux ressources, jeu d'instructions processeur réduit.
2. **Mode noyau (ou superviseur)** : accès libre aux ressources, jeu d'instructions complet. Noyau préemptible (un processus en mode noyau peut être interrompu par un autre) ou non.

**2)** 3 cas possibles :

1. le processus invoque une fonction système (explicite) ;
2. le processus exécute une opération illicite (division par 0, violation mémoire, ...) : provoque une exception, ou trappe (arrêt du processus) ;
3. le système reçoit une interruption matérielle qui provoque l'exécution de la routine d'interruption associée.

**3)**

- **API** : Application Programming Interface
- **SVC** : SuperVisor Call
- **PCB** : Process Control Bloc
- **IPC** : InterProcess Communication

**4)** On choisit `pthread_create()` car, dans le cas d'une duplication, `fork()` est plus coûteux en termes d'espace mémoire et d'exécution (commutation de processus). Pour les threads, il y a un partage de ressources entre les threads au niveau du processus créateur, ainsi il faut faire attention aux conflits d'accès.

</details>

## Exercice 1 : Processus Unix (4,5 points)

**1)** Écrire un programme qui engendre un processus et se termine. Le processus fils, dès qu'il devient orphelin, affichera à l'écran un message permettant à l'utilisateur de se convaincre que ce processus est orphelin. (2,5 points)

<details>
<summary>Correction — orphelin.c</summary>

```c
#include <unistd.h>
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    switch (fork()) {
        case -1:
            exit(EXIT_FAILURE);
        case 0:
            sleep(2);
            printf("Mon pere est %d (init).\n", (int) getppid());
        default:
            exit(EXIT_SUCCESS);
    }
}
```

</details>

## Exercice 2 : Parking de N places (7 points)

Un parking de N (N>2) places est géré par le contrôle des entrées/sorties des voitures et des camions. Une voiture utilise une seule place alors qu'un camion a besoin de deux places (consécutives) pour se garer.

**1)** En utilisant les sémaphores, proposez une solution de synchronisation des processus camions et voitures (par simplicité, on suppose que les véhicules seront toujours garés dans l'ordre de gauche à droite, même s'il y a des sorties). Précisez les données partagées ainsi que l'initialisation des sémaphores. (5,5 points)

**2)** Modifier la solution proposée pour favoriser les voitures. (1,5 points)

<details>
<summary>Correction</summary>

**1)**

Cas critiques : une voiture se bloque quand il n'y a pas de place libre. Un camion se bloque quand il n'y a pas au moins 2 places consécutives libres, ou le parking est plein.

Hypothèse : on considère qu'on dispose d'un tableau de N places et que les véhicules sont toujours garés dans l'ordre, même s'il y a des sorties. En d'autres termes, on ne permet pas d'avoir des trous dans le parking.

Variables partagées :

```c
semaphore places = N; // N places possibles pour les voitures de se garer
```

Processus Voiture :

```c
P(places);
GARER sa voiture
V(places);
```

Processus Camion :

```c
P(places);
P(places);
Garer son camion
V(places);
V(places);
```

**2)** Il suffit de rajouter un sémaphore `priorite`, initialisé à 1, et d'encadrer le processus le moins prioritaire (c-à-d Camion) par `P(priorite)` et `V(priorite)`.

Variables partagées :

```c
semaphore places = N; // N places possibles pour les voitures de se garer
semaphore priorite = 1; // priorité des voitures
```

Processus Voiture :

```c
P(places);
GARER sa voiture
V(places);
```

Processus Camion :

```c
P(priorite);
P(places);
P(places);
Garer son camion
V(priorite);
V(places);
V(places);
```

</details>

## Exercice 3 : Partage d'imprimantes (4 points)

Un ensemble de N (N>4) processus partagent 3 imprimantes LP0, LP1, LP2. Pour éviter de mélanger les lignes sorties de chaque processus, le processus Pi doit réserver l'imprimante avant de l'utiliser. Pour connaître l'état de chaque imprimante il y a une variable globale `int LP[3]`. Les codes des deux fonctions `prendre()` et `liberer()` sont comme suit :

```c
int prendre() {
    int i = 0;
    while (i < 3) {
        if (LP[i] == 0) {
            LP[i] = getpid();
            return i;
        }
        ++i;
    }
    return -1;
}

int liberer(int i) {
    LP[i] = 0;
}
```

En utilisant 2 sémaphores, complétez `prendre()` et `liberer()` pour synchroniser entre les N processus.

<details>
<summary>Correction</summary>

Variables partagées :

```c
int LP[3] = {0, 0, 0}; // tableau de 3 imprimantes : 0 → libre, 1 → réservée
semaphore mutex = 1; // protection d'accès au tableau LP en exclusion mutuelle
semaphore printer = 3; // 3 imprimantes disponibles
```

```c
int prendre() {         // (2 pts)
    int i = 0;
    P(printer);
    P(mutex);
    while (i < 3) {
        if (LP[i] == 0) {
            LP[i] = getpid();
            V(mutex);
            return i;
        }
        ++i;
    }
    V(mutex);
}

int liberer(int i) {    // (1,25 pts)
    P(mutex);
    LP[i] = 0;
    V(mutex);
    V(printer);
}
```

</details>
